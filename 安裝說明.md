### GNAI 安裝權限注意事項

> **請使用一般使用者權限的 PowerShell 或 Command Prompt 安裝及設定 GNAI，不要使用「以系統管理員身分執行」。**

`Chat_Mode_Assistant_Setup_0.1.13.5.exe` 本身也不需要系統管理員權限；它會以目前使用者身分安裝到 `%LOCALAPPDATA%`，並在 `HKCU` 註冊 Native Messaging Host。

下列操作應全部由日後實際使用 Chat Mode Assistant 的同一個一般 Windows 使用者執行：

- `dt.exe install`
- `dt extensions enable gnai`
- `dt gnai update`
- `dt gnai config set-credentials`
- `dt gnai toolkits register ...`
- GNAI 首次啟動及 Toolkit 首次初始化

若使用 Admin Terminal 安裝或初始化，GNAI 的設定、credential、Toolkit cache 或相關檔案可能被寫入不同的 `%USERPROFILE%`，或建立只有 elevated process 才能完整存取的 ACL。這可能造成一般權限 Bridge 可以啟動 `dt gnai chat` 並顯示 Welcome，但送出問題後停在 `Asking GNAI` 而沒有回應。

若曾使用 Admin Terminal 安裝且發生上述問題，建議以一般使用者權限重新執行 GNAI 安裝、credential 設定、Toolkit register 與首次初始化，並確認一般 Terminal 執行 `dt gnai chat` 可以正常取得回覆後，再啟動 Chat Mode Assistant。

## 一般使用者安裝（使用 .exe 安裝檔）

### 步驟 0（建議）：執行環境檢查

執行安裝檔後，安裝精靈會顯示 **Environment Check** 頁面，點擊 **Run Environment Check** 按鈕即可執行內建的環境檢查；也可以直接點擊 **Next** 跳過。`check_env.exe` 只會暫時解出執行，不會永久安裝到安裝目錄，也不會影響安裝流程。

也可以在安裝前單獨執行與 installer 一同提供的 `check_env.exe`。兩種方式使用相同的檢查程式。

檢查項目：

| 項目            | 說明                              |
| --------------- | --------------------------------- |
| Intel`dt` CLI | 是否在 PATH 中                    |
| GNAI 認證       | `dt gnai` 是否可正常使用        |
| sighting        | Toolkit 安裝 |
| displaydebugger | Toolkit 安裝 |
| sherlog         | Toolkit 安裝 |

每項顯示格式：`Toolkit: installed`

> 顯示 **✗（紅色）** 表示 Toolkit 未安裝或認證失敗。

**自動安裝缺少的 Toolkit**：當某個 Toolkit 顯示「not installed」時，該列下方會出現 **▶ Install** 按鈕，點擊後會開啟 PowerShell 視窗自動執行對應的 register 指令，安裝完成並關閉視窗後會自動重新檢查。對應指令如下：

| Toolkit         | 安裝指令                                                                         |
| --------------- | -------------------------------------------------------------------------------- |
| sighting        | `dt gnai toolkits register intel-sandbox/SightingAssistantTool`                |
| displaydebugger | `dt gnai toolkits register intel-sandbox/displaydebugger`                      |
| sherlog         | `dt gnai toolkits register intel-innersource/drivers.gpu.core.sherlog-toolkit` |

**載入建議 Config（強烈建議）**：當 `sighting` Toolkit 檢查通過（顯示 ✓）後，該列下方會出現 **⚙ Apply Recommended Config** 按鈕。點擊後會將建議的 `config.local.json` 寫入 sighting toolkit 的安裝目錄，套用以下設定：

| 設定項目                     | 值                                    | 說明                                      |
| ---------------------------- | ------------------------------------- | ----------------------------------------- |
| `table_output_format`      | `true`                              | 以表格格式輸出分析結果，排版更易讀        |
| `state_tokens_enabled`     | `false`                             | 關閉 state token，避免干擾 Extension 解析 |
| `verbose_progress_updates` | `false`                             | 關閉冗長進度訊息，減少不必要輸出          |
| `html_report_generation`   | `false`                             | 關閉 HTML 報告，僅使用純文字輸出          |
| `subprocess_pause`         | `true`（displaydebugger / sherlog） | 子視窗執行完後暫停，方便手動檢視          |
| `cache.enabled`            | `true`                              | 啟用 RAG cache，加速後續查詢              |

> 套用後按鈕會變為 **✓ Config Applied**，設定檔路徑會顯示在彈窗中確認。若 sighting 尚未安裝，請先點擊 **▶ Install** 完成安裝再套用。

建議所有項目顯示 ✓ 後再繼續安裝。無論檢查結果如何，安裝精靈都不會阻止你繼續安裝；關閉檢查程式後即可點擊 **Next** 繼續。

### 步驟 1：執行安裝檔

執行 `Chat_Mode_Assistant_Setup_0.1.13.5.exe`，依照精靈指示完成安裝。請勿選擇「以系統管理員身分執行」。

- 預設安裝路徑：`%LOCALAPPDATA%\ChatModeAssistant\`（不需要系統管理員權限）
- 安裝精靈會自動在目前使用者的 Registry（HKCU）註冊 Native Messaging Host。使用 installer 時不需要執行 `bridge\install_native_host.ps1`；該腳本僅供原始碼開發或手動修復使用。

### 步驟 2：載入 Chrome Extension

安裝完成後，精靈會自動開啟 extension 資料夾：

1. 開啟 Chrome，前往 `chrome://extensions/`
2. 右上角開啟「**開發人員模式**」
3. 點擊「**載入未封裝項目**」→ 選擇安裝目錄內的 `extension\` 資料夾
   - 預設路徑：`%LOCALAPPDATA%\ChatModeAssistant\extension\`
4. 載入後 **Extension ID** 固定為 `pmbnnkfhdkommfpphknjpppmlmbihomi`

> Extension 的 `manifest.json` 內含固定的 `key`，因此 Extension ID 永遠相同，且已預先寫入 Native Messaging 設定，**不需要額外設定 Extension ID**。

### 步驟 3：執行 `dt gnai update`

在使用本工具前，執行 `dt gnai update`，確定 GNAI 相關 SDK 都有正確安裝。

### 步驟 4：驗證

1. 點擊 Extension icon 開啟 Side Panel。
2. Bridge 只會在 Side Panel 真正顯示後啟動；Chrome 啟動或隱藏的 Side Panel 不會預先啟動 Bridge。
3. 狀態應顯示 "Connected"。若剛載入 Extension 後無法連線，重新啟動 Chrome 再試一次。

### 覆蓋升級

直接執行較新版本的 `Chat_Mode_Assistant_Setup_X.Y.Z.exe`，不需要先解除安裝。升級程序會：

- 暫時停用 Native Messaging，並結束既有的 `native_host.exe` 與 `bridge_server.exe` process tree。
- 完整重建 `extension\`，並清除舊版 `configure.exe`、`bridge.pid`、`bridge.port`、`bridge.discovery.json`。
- 保留 Bridge log、driver history、build cache、Chrome 本機儲存的聊天紀錄，以及 `~/.gnai` 的 credentials、config 與 toolkits。
- 升級完成後，前往 `chrome://extensions/`，在 Chat Mode Assistant 上點擊重新載入圖示。既有 Extension 不需要再次執行 Load unpacked。

## English Installation Guide

### Prerequisites

| Item | Requirement |
| ---- | ----------- |
| **Windows 10/11** | Windows only |
| **Git for Windows** | For install toolkits, need to install [Git for Windows](https://git-scm.com/install/windows) |
| **Intel Developer Toolkit CLI (`dt`)** | [Download `dt.exe`](https://gfx-assets.intel.com/artifactory/gfx-build-assets/build-tools/devtool-go/latest/artifacts/win64/dt.exe), run `dt.exe install`, and confirm `dt` is in `PATH` |
| **GNAI access** | Request "GNAI Chatbot GPU Top Secret" access through AGS. See [intel-sandbox/displaydebugger](https://github.com/intel-sandbox/displaydebugger) |
| **GNAI extension** | Run `dt extensions enable gnai` |
| **GNAI credentials** | Run `dt gnai config set-credentials` |
| **Google Chrome** | Required to load the extension |
| **`tracefmt`** | Required only for DisplayDebugger ETL analysis; install the [Windows SDK](https://developer.microsoft.com/en-us/windows/downloads/windows-sdk/) and add `tracefmt.exe` to `PATH` (normally under `C:\Program Files (x86)\Windows Kits\10\bin\10.0.XXXXXX.0\x64\`) |
| **Python** | Not required for end users; required only to build the installer |

### GNAI permission requirement

> **Install and configure GNAI from a non-administrator PowerShell or Command Prompt. Do not use "Run as administrator."**

Run all of the following as the same standard Windows user who will use Chat Mode Assistant:

- `dt.exe install`
- `dt extensions enable gnai`
- `dt gnai update`
- `dt gnai config set-credentials`
- `dt gnai toolkits register ...`
- The first GNAI launch and each toolkit's first initialization

The `Chat_Mode_Assistant_Setup_0.1.13.5.exe` installer also requires no administrator privileges. It installs under `%LOCALAPPDATA%` and registers the Native Messaging Host under `HKCU`.

Using an administrator terminal can store GNAI settings, credentials, toolkit caches, or ACLs under a different `%USERPROFILE%`. A non-admin Bridge may then reach the GNAI Welcome prompt but remain at `Asking GNAI` after a question is sent. If this happened, repeat the GNAI installation, credential setup, toolkit registration, and first initialization as the standard user. Confirm that `dt gnai chat` returns a response in that user's terminal before opening Chat Mode Assistant.

### Step 0 (recommended): Check the environment

The installer displays an **Environment Check** page. Click **Run Environment Check** to launch the built-in checker, or click **Next** to skip it. It extracts `check_env.exe` temporarily and does not install that executable permanently, and does not block installation either way. The separately supplied `check_env.exe` runs the same checks and can be used before installation.

The checker verifies:

- Intel `dt` CLI in `PATH`
- GNAI authentication and connectivity
- Toolkit installation for `sighting`, `displaydebugger`, and `sherlog`

A red **failure** means the toolkit is missing or authentication failed.

When a toolkit is missing, use its **Install** button to open PowerShell and run the corresponding registration command. The checker reruns automatically after that window closes.

| Toolkit | Registration command |
| ------- | -------------------- |
| sighting | `dt gnai toolkits register intel-sandbox/SightingAssistantTool` |
| displaydebugger | `dt gnai toolkits register intel-sandbox/displaydebugger` |
| sherlog | `dt gnai toolkits register intel-innersource/drivers.gpu.core.sherlog-toolkit` |

After `sighting` passes, use **Apply Recommended Config** to write the recommended `config.local.json` into the installed sighting toolkit directory.

| Setting | Value | Purpose |
| ------- | ----- | ------- |
| `table_output_format` | `true` | Format analysis results as readable tables |
| `state_tokens_enabled` | `false` | Prevent state tokens from interfering with extension parsing |
| `verbose_progress_updates` | `false` | Reduce unnecessary progress output |
| `html_report_generation` | `false` | Use plain-text output without HTML report generation |
| `subprocess_pause` | `true` for displaydebugger and sherlog | Keep child windows open for manual inspection |
| `cache.enabled` | `true` | Enable the RAG cache for faster later queries |

After applying the file, the button changes to **Config Applied** and the confirmation dialog shows its path. Install sighting first if the button is not available.

It is recommended to resolve failed checks before continuing, but the installer never blocks installation on the result. Close the checker and click **Next** to continue whenever you are ready.

### Step 1: Run the installer

Run `Chat_Mode_Assistant_Setup_0.1.13.5.exe` and follow the wizard. Do not use "Run as administrator."

- Default install path: `%LOCALAPPDATA%\ChatModeAssistant\`
- The installer registers the Native Messaging Host automatically.
- Do not run `bridge\install_native_host.ps1` when using the installer; that script is only for source-based development or manual recovery.

### Step 2: Load the Chrome extension

After installation, the wizard opens the installed `extension\` folder.

1. Open `chrome://extensions/` in Chrome.
2. Enable **Developer mode**.
3. Select **Load unpacked** and choose `%LOCALAPPDATA%\ChatModeAssistant\extension\`.
4. Confirm that the Extension ID is `pmbnnkfhdkommfpphknjpppmlmbihomi`.

The fixed `key` in `manifest.json` keeps this ID stable. The installer already writes the same ID to the Native Messaging configuration; no manual Extension ID setup is required.

### Step 3: Run `dt gnai update`

Before using this tool, run `dt gnai update` to confirm the GNAI-related SDKs are installed correctly.

### Step 4: Verify

1. Open the Side Panel from the extension icon.
2. The Bridge starts only when the Side Panel is actually visible. Starting Chrome or restoring a hidden Side Panel does not start it early.
3. Confirm that the status becomes **Connected**. If the extension was just loaded and cannot connect, restart Chrome once and retry.

### In-place upgrade

Run the newer `Chat_Mode_Assistant_Setup_X.Y.Z.exe` directly; do not uninstall the existing version first.

- The installer temporarily disables Native Messaging and stops the existing `native_host.exe` and `bridge_server.exe` process tree.
- It rebuilds `extension\` and removes obsolete `configure.exe`, `bridge.pid`, `bridge.port`, and `bridge.discovery.json` files.
- It preserves Bridge logs, driver history, build cache, Chrome local chat history, and the credentials, configuration, and toolkits under `~/.gnai`.
- After the upgrade, open `chrome://extensions/` and click Reload for Chat Mode Assistant. Do not use Load unpacked again for an existing installation.

## 架構概覽

```
Chrome Extension (background.js Service Worker)
   │
   ├─①─ Native Messaging ──► native_host.exe ──背景啟動──► bridge_server.exe
   │     "launch" / "check"                    （隱藏視窗）       │
  │     Side Panel 可見後才啟動           寫入 bridge.port ◄────────┘
   │     （輪詢取得埠號後即不再使用）
   │
   └─②─ HTTP / SSE ──────────────────────────────────────► bridge_server.exe
         取得埠號後直接連線                                        │  winpty / ConPTY
         所有後續通訊皆走此路徑                                    ▼
                                                           dt gnai chat --json
                                                               --assistant <name>
```

**Lazy startup 與埠號協定**：Side Panel 真正顯示後，background.js 才透過 Native Messaging 傳送 `launch`；hidden Side Panel 或單純啟動 Chrome 不會啟動 Bridge。bridge_server 啟動後將實際埠號（預設 8776，若佔用則自動選空閒埠）寫入 `bridge.port` 及 discovery 資訊；background.js 透過 Native Messaging 輪詢 `check`，取得並驗證埠號後快取到 `chrome.storage.session`，Service Worker 重啟後仍可復用。

**Service Worker Keep-alive**：session 進行中，background.js 每 20 秒自我 ping 一次，避免 Chrome 在 AI 長時間執行 tool 時將 Service Worker 暫停，同時監控 SSE 連線並自動重連。

### Bridge Server 端點

| 方法         | 路徑                       | 說明                                                     |
| ------------ | -------------------------- | -------------------------------------------------------- |
| `GET`      | `/health`                | 健康檢查，回傳 session 狀態與 session_id                 |
| `POST`     | `/session/start`         | 建立新 chat session（指定 assistant 與 conversation_id） |
| `POST`     | `/session/send`          | 傳送訊息到 active session                                |
| `GET`      | `/session/stream`        | SSE 串流，接收 AI 回覆事件                               |
| `POST`     | `/session/stop`          | 終止 active session                                      |
| `GET/POST` | `/driver-history`        | 讀寫 GFX/GOP driver regression 歷史紀錄                  |
| `POST`     | `/driver-history/delete` | 刪除指定 driver history 條目                             |
| `POST`     | `/build-cache/lookup`    | 查詢 per-version build 快取                              |
| `POST`     | `/build-cache/save`      | 儲存 build 快取條目                                      |
| `GET`      | `/dialog/file`           | 開啟系統檔案選擇對話框（回傳選取路徑）                   |
| `POST`     | `/bridge/shutdown`       | 關閉 bridge server 程序                                  |

### Extension ID（setup.iss）

Extension 的 `manifest.json` 內含固定 `key`，因此 Extension ID 恆為：

```ini
#define ExtensionId "pmbnnkfhdkommfpphknjpppmlmbihomi"
```

此 ID 已寫死在 `setup.iss`，安裝時用於產生 `nm_manifest.json` 的 `allowed_origins`。除非更換 `manifest.json` 的 `key`，否則不需修改。

## 已知問題與解決方法

| 問題                 | 原因                                       | 解決方法                                                                                        |
| -------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| 狀態顯示 "No Bridge" | Native Messaging 未正確設定                | 重新執行安裝檔，確認 Registry 中已註冊`com.chat_mode_assistant.bridge`                        |

## Check GFX/GOP Driver Regression 功能說明

GFX/GOP Driver Regression 目前還在測試中，可能無法正常使用

### 使用方式

在 Side Panel 內，對話視窗頂端有兩個按鈕：

| 按鈕          | 功能                                         |
| ------------- | -------------------------------------------- |
| **GFX** | 對當前 HSD 進行 GFX Driver Regression 分析   |
| **GOP** | 對當前 HSD 進行 GOP Firmware Regression 分析 |
| **H**   | 開啟 History 面板（顯示過去的查詢結果）      |
| **C**   | 清除當前 HSD 的所有 Regression 記錄          |

### 查詢流程

```
點擊 GFX / GOP
  ↓
① 同一 HSD History lookup（by hsd_id）       ← 最快，直接顯示
  ↓（沒找到）
② Cross-HSD History lookup（by fail/pass 版本）← 其他 HSD 有相同版本直接借用
  ↓（沒找到）
③ Per-version Build Cache（組裝個別 build）  ← 跳過 QuickBuild 登入
  ↓（沒找到）
④ QuickBuild 登入後重新查詢
```

### 第一次使用前提

- 需要有 QuickBuild 帳號（Intel 內部網路）
- 第一次查詢每個版本組合時，會彈出 QB 登入視窗
- 查詢結果會自動存入本機 History Cache，後續相同版本不需重新登入

### History Cache 存放位置

安裝後 cache 存放於安裝目錄：

```
%LOCALAPPDATA%\ChatModeAssistant\
├── driver_history_gfx.json   ← GFX 查詢紀錄
├── driver_history_gop.json   ← GOP 查詢紀錄
├── build_cache_gfx.json      ← GFX per-version build 快取
└── build_cache_gop.json      ← GOP per-version build 快取
```

## 環境變數（可選）

| 變數                 | 預設值             | 說明                     |
| -------------------- | ------------------ | ------------------------ |
| `BRIDGE_PORT`      | 8776               | Bridge Server 監聽 Port  |
| `BRIDGE_HOST`      | 127.0.0.1          | Bridge Server 監聽 IP    |
| `BRIDGE_ASSISTANT` | sighting_assistant | 預設 GNAI Assistant 名稱 |
| `BRIDGE_DT_PATH`   | （空，自動搜尋）   | 指定 dt CLI 路徑         |
| `BRIDGE_DEBUG`     | 1                  | 啟用 debug log           |

## 安裝目錄結構（安裝後）

```
%LOCALAPPDATA%\ChatModeAssistant\
├── bridge_server.exe          ← Bridge Server（獨立執行，不需 Python）
├── native_host.exe            ← Native Messaging Host（Chrome 自動呼叫）
├── nm_manifest.json           ← Native Messaging 設定（安裝時自動生成）
├── extension\                 ← Chrome Extension（Load unpacked 此資料夾）
│   ├── manifest.json
│   ├── background.js
│   ├── sidepanel.html
│   ├── sidepanel.js
│   ├── regression_ui.js
│   └── icons\
│
│  ── 以下為執行期自動產生，安裝後不存在 ──
│
├── bridge.port                ← Bridge 實際監聽埠號（bridge_server 啟動時寫入）
├── bridge_debug.log           ← Bridge debug log（BRIDGE_DEBUG=1 時產生）
├── bridge.pid                 ← Bridge 程序 PID（解除安裝時自動清除）
├── driver_history_gfx.json    ← GFX regression 查詢紀錄（首次查詢後產生）
├── driver_history_gop.json    ← GOP regression 查詢紀錄（首次查詢後產生）
├── build_cache_gfx.json       ← GFX per-version build 快取（首次查詢後產生）
└── build_cache_gop.json       ← GOP per-version build 快取（首次查詢後產生）
```

> installer 內含 `check_env.exe` 供安裝時暫時執行，但不會把它永久安裝到此目錄；建置輸出另附一份可重複執行的獨立 `check_env.exe`。
